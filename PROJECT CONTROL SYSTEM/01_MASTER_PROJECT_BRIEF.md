# 01 — Master Project Brief

Status: APPROVED foundation
Project: Master Hub

## Identity
- Project name: Master Hub
- Product category: Personal command center / application registry / project operating system
- One-sentence definition: A single command center that provides direct access to the owner's operational apps while maintaining a controlled source of truth for project state and execution.
- Detailed definition: Master Hub unifies app access, action tracking, field-service resources, finance tooling, repair-package workflows, and project governance without inventing fake data or hiding unresolved state.
- Vision: One durable place to find, run, understand, maintain, and recover the owner's tools.
- Mission: Reduce fragmentation and AI/project drift by keeping execution, evidence, decisions, and current state explicit.
- Product promise: What is shown as implemented, tested, verified, or live must be supported by evidence.

## Problem
The owner has multiple tools, deployments, evolving requirements, and historical decisions. Conversation history and disconnected deployments are not reliable enough to serve as the system of record.

## Users
- Primary user: Project Owner
- Secondary users: UNKNOWN / NEEDS CONFIRMATION
- Professional users: Field-service technicians where specific field tools are shared
- Administrators: Project Owner; additional administrators UNKNOWN / NEEDS CONFIRMATION

## Core Product
The Master Hub web application plus this Project Control System.

## Core Workflow
Need / evidence → classify → decide → require → implement → test → verify → release → accept → back up → baseline.

## Inputs
Owner instructions, repository state, imported operational data, source documents, deployment evidence, test results, and approved integrations.

## Outputs
Working tools, controlled project records, current-state summaries, traceable decisions, verified releases, and recoverable baselines.

## AI Role
AI may organize evidence, draft controlled changes, implement approved work, identify gaps, and report verification status. AI may not silently convert unknown/proposed items into approved scope or claim deployment/test success without evidence.

## Human Role
The Project Owner approves scope, constitutional changes, final acceptance, destructive changes, and unresolved business/product choices.

## MVP
APPROVED current boundary:
- Master Hub dashboard/directory/actions
- Direct access to approved apps and internal routes
- Field Resource / Diagnostic functionality
- Repair Packages
- Finances Command Center
- Permanent Project Control System

## Post-MVP
UNKNOWN / NEEDS CONFIRMATION unless separately approved.

## Non-Goals
- Fake/demo project state
- Silent scope expansion
- Treating conversational memory as canonical
- Claiming build/deployment success without verification

## Known Risks
- Multiple Vercel projects have historically been connected to the same repository.
- Public repository content must not contain private financial or secret data.
- Some standalone tools and aliases can diverge from the canonical Master Hub source.
- Historical conversation decisions may not yet be fully reconstructed into this control system.
